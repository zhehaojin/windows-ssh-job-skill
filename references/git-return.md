# 结果回传与发布

上传需要用户授权的目标仓库与新分支。远程 SSH 密码不等于 GitHub 凭据；结果发布使用本机已有 Git 身份和 GitHub 登录。没有登录或写权限时说明具体缺项，不把密码放到 URL，也不自动创建 token。

1. 按应用约定确认运行终态、退出码和结果完整性；同时保留成功、失败及所有 seed，不能用测试结果筛选上传内容。
2. 拉取结果并核对需要的 SHA-256。远程原目录只读，整理一个专用于发布的本地副本。
3. 移除凭据、环境、连接配置和原始输入。将副本内绝对机器路径相对化，留意 CSV 中的 JSON 字符串和嵌套诊断字段；不修改数值和失败原因。若导出内容变化，记录原始与导出哈希。
4. 调用 `scripts/publish-results.ps1`，明确指定 HTTPS GitHub URL、全新结果分支、ResultsDirectory、WorkDirectory。可先 DryRun。脚本只在独立 clone 中操作，不改变当前仓库或暂存区。
5. 核对返回状态和远端分支提交后报告链接。已有分支不覆盖；要重复发布时使用明确的新分支或先人工核对旧内容，不扩大为覆盖权限。

只创建新引用的精确 empty-expectation lease 不允许更新既有分支；脚本不使用普通强制推送。GitHub URL 不接受 token 或 userinfo。

`ResultsDirectory` 必须是已审阅的发布副本。脚本排除常见敏感/环境项并返回数量，但无法证明任意业务文件都没有秘密；不能把原始 run 根目录盲目当成发布目录。符号链接与单文件达到 50 MiB 的内容会停止 Git 发布，改为用户授权的 Release 附件等方式处理。

自动上传是一项独立调度任务，需要保存明确的 run ID、完成判据、目标分支和幂等状态。没有外部调度时，普通 skill 和一次性脚本不会在未来自动唤醒。
